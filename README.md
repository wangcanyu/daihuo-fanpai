# daihuo-fanpai · 爆款带货短视频复刻 skill

反推爆款带货短视频 → 迁移到你的产品 → 即梦/Seedance 重新生成镜头 → 配音、拼接、评分 → **交付剪映草稿或烧字幕成品**。
一个 **agent 驱动**的流水线(为 [Claude Code](https://claude.com/claude-code) 等 agent 设计),每步产物都是可人工审改的文件。

> **核心洞察**:复刻带货视频"agent 不如手工"的根因**不是生成模型,而是"反推→写提示词"的转换环节会丢细节、丢动作**——反推明明抓到了"橙色草本水、一只手把海参掰开",写提示词时被概括没了。本项目所有设计都在守一条:**把反推到的主体+动作+关键细节原样带进生成**,再用完备性关卡、人审闸口、评委三道判断兜底。

## 能做什么

| 模式 | 说明 | 实测评委分(三看漏斗90分制) |
|---|---|---|
| **A 忠实复刻** | 原台词、原产品,原原本本复刻 | 54/90 |
| **产品迁移** | 目标视频结构 + 换成你的产品/包装 | 包装文字保真 |
| **B 跨类目复刻** | 借别品类爆款结构 + 方法论本地化台词 | 69/90 |
| **A 群戏情景剧** | 三角色办公室短剧复刻(多人锚定+原音对口型) | 保真度 63/100,产品还原 16/20 |
| **A 量产模式** | 同产品全目录批量复刻(SOP 全自动) | 实测单日 16 条交付,后期稳定 40-60 分钟/条 |

分数越高越"能跑量"。跨类目(理解后重构)分最高——**方法论指导的重构 > 机械复刻**。剧情流原片按千川 rubric 打分天然偏低,看保真度即可。历史最高三看分 75/90(口播型忠实复刻)。

## 流水线

```
0 体检(doctor) → 1 反推(seed_reverse) → [1b 双反推:k3_reverse + merge_reverse 证据合并裁决]
→ 1.5 ★资产清单(needed_assets:要哪些产品图/人物/场景,并分清【谁来准备】)
→ 1.6 ★演职表(cast_plan 聚角色 → 人审 → make_cast_sheet 出 3:4 人设图入库)
→ 1.7 ★场景(scene_plan 收敛逐镜场景 → make_scene 出场景板)
→ 1.8 ★说话人标注(speaker_tag:逐句判 旁白/同期声 + 说话人 → 人审 → 写回 shotlist)
→ 2 规划(plan_segments,完备性关卡+人审 segments.md) → [群戏:patch_cast 多人锚定+人数硬约束]
→ [B模式:脚本本地化 localize_seed / localize_apply + 人审]
→ 3 配音(tts_segments,多说话人+读音修正 | 原音复用:cut_audio 切段+2秒闸+精确字幕轴)
→ 4 生成(gen_segments,即梦/火山/小云雀/海螺四后端;口播段可走即梦或海螺;
     --concurrency 并发提交(仅对验证过的后端);口播时长自动对齐配音;TNS/网络抖动自动重试)
→ 5 装配(assemble) → [质检:qc_lipsync 帧级口型 / ★qc_cast 人物跨镜一致性+旁白镜口型]
→ 6 评委(judge,成片+原片真对比) → 7 字幕(export_subs → SRT+贴字清单)
→ 8 交付(deliver:★剪映草稿——五轨就位打开即剪 | 烧字幕+BGM 一步到位成品)
```

★走 h3 腿(mmh3/rh)时,规划后还有两步:`h3_prompt.py` 转六段式提示词并**灌回 segments.json**
(gen_segments 只读 plan,不读 prompts/ —— 不灌回就会拿旧提示词生成且全程不报错),
再过 `director.py` 的 12 条约束闸(含 prompts/ ⇄ plan 漂移检查)。

每一步只通过 JSON 文件/文件夹交接,**可插拔**——换反推 VLM、换视频模型、换 TTS,只改对应一个脚本(契约见 `DESIGN.md`)。

## 引擎脚本(34)

| 脚本 | 作用 |
|---|---|
| `doctor.py` | 环境体检(依赖分级:轻依赖可自动装/凭证与重型依赖提示用户) |
| `seed_reverse.py` | 反推:原生视频 → 结构化分镜表(硬切/台词/product_role/host_on_camera/关键颜色) |
| `k3_reverse.py` | 双反推第二腿(Kimi K3,同 SCHEMA 同切点源):运镜时间轴强,实体描述必须帧验 |
| `merge_reverse.py` | 双反推证据合并:逐镜并排 dossier + 分歧信号灯 + 分歧点自动抽帧 + 静音闸 |
| `cut_audio.py` | 原音复用切段:按段边界切原片音频,内置**即梦2秒上传下限闸**,顺产镜级 timing.json 字幕轴 |
| `patch_cast.py` | 群戏/多人补丁:按出镜角色挂锚图+逐角色声明+**人数硬约束句**(群戏生命线) |
| `qc_lipsync.py` | 帧级口型质检:原片帧=谁张嘴的真值,AI 帧只答"谁在张嘴"——**杜绝模型看片幻听转写** |
| `needed_assets.py` | 反推后列出这条片要哪些资产,**并分清谁来准备**(产品=你;人物/场景=AI 生成你审;道具看情况)+ assets 骨架 |
| `cast_plan.py` | 从 `person` 字段聚出角色候选(**必须人过目**);带【单主播片闸】(多日 vlog 的换装会被聚成假角色)和【人称名词闸】 |
| `make_cast_sheet.py` | AI 生成 **3:4 人设图**(上排三肖像+下排三全身,灰底影棚)并入资产库;规格由 A/B/C/C2 四版实测定 |
| `scene_plan.py` | 把逐镜各写各的 `scene` 收敛成几个共用场景(实测 58 镜 43 种说法 → 2 个场景) |
| `make_scene.py` | 每个场景生成一张**场景板**(不含人物),全片共用,治"每段各编一个地方" |
| `speaker_tag.py` | VLM **一次看全片(带音轨)** 判每句是 旁白/同期声 + 说话人 → 治"旁白镜里所有人对着画外音张嘴" |
| `qc_cast.py` | 人物跨镜一致性验收(段内逐镜横排比对) + **旁白镜口型验收**(镜内多点采样看嘴有没有开合) |
| `plan_segments.py` | 分段/路由/写提示词(动作原样带全)+ 完备性关卡 + 人审稿;`--min-dur/--hard-max-cuts` 填满模式治后端最短时长的浪费 |
| `localize_seed.py` | B模式脚本本地化初稿(喂方法论弹药包起草) |
| `localize_apply.py` | 把改好的台词写回分镜表(自动同步口播提示词保口型) |
| `tts_segments.py` | 配音:CosyVoice 多说话人 A/B + 多音字读音修正(可配置词表) |
| `gen_segments.py` | 生成:即梦/火山/小云雀/海螺四后端(`--i2v-backend` 切 i2v 段、`--mm-backend` 切口播段);**即梦默认走非 VIP 慢速排队档**(比 VIP 便宜 43%,`--jimeng-model` 可切快速档/2.5);口播时长自动对齐配音;**提交退避重试+下载解码体检**(坏字节流自动重下) |
| `ark_gen.py` | 火山 Ark Seedance 2.0 后端(按 token 计费,省 CLI 积分池;含人脸参考图会被政策拦截,只走纯产品 i2v) |
| `xyq_gen.py` | 小云雀后端(独立 credits 池;参考重绘语义,只接无文字要求的氛围镜) |
| `mmh3_gen.py` | **MiniMax H3 官方规范后端(h3 首选)**:`base_url` 可换渠道(秘塔 768P ≈¥0.11/秒,官方直连/自部署同样可接);多锚图+音频驱动口型。用前读 `references/h3/README.md` |
| `rh_gen.py` | RunningHub 海螺 h3(同模型但渠道价贵 4.4 倍,**已退役**,留作后路) |
| `assemble.py` | 逐段归一化拼接 + 铺连续配音轨;`--trim-to-plan` 裁回规划跨度治段尾空窗,`--master-audio` A模式整条原音直铺,`--size` 输出画幅(2K素材别用默认720p) |
| `judge.py` | 评委:三看漏斗 90 分打分;`--target` 时**成片+原片一起上传做真保真度对比** |
| `export_subs.py` | 导出句级 SRT 字幕 + 原片屏上贴字清单(剪映照抄) |
| `vc_segments.py` | **换声不换演**(Seed-VC):原片切段音频转目标音色,表演节奏逐帧保留;治"复用原音怕查重/TTS重配丢表演"两难(单主播片;群戏需说话人分离未实现) |
| `deliver.py` | **交付**(`--trim-to-plan/--size` 需与装配同口径):剪映草稿(视频/配音/字幕/贴字参考/空BGM 五轨,素材自包含,打开草稿箱即剪)或烧字幕+BGM 成品;字幕轴优先吃 TTS 句级真实时长 |
| `config.py` | 密钥/模型/路径集中配置(全部环境变量可覆盖,无硬编码) |

## 快速开始

### 用 agent 安装(推荐)

整个仓库就是一个 skill,装法就是克隆到 agent 的 skills 目录。打开 Claude Code,发这句话:

```
把 https://github.com/wangcanyu/daihuo-fanpai 克隆到 ~/.claude/skills/daihuo-fanpai,
然后进目录跑 python3 doctor.py 体检,轻依赖直接帮我装好,凭证类告诉我怎么配
```

装完**重开一个会话**(skill 列表在会话启动时加载),之后说人话就能开工,agent 会自动触发 skill、按流水线跑、该人审的地方停下来等你过稿:

```
复刻这条带货视频:目标.mp4,原台词原产品                    ← A 模式
把 目标.mp4 换成我的海参重做一条,台词按我的产品本地化       ← B 模式
```

等价的手动安装:

```bash
git clone https://github.com/wangcanyu/daihuo-fanpai.git ~/.claude/skills/daihuo-fanpai
cd ~/.claude/skills/daihuo-fanpai && python3 doctor.py
```

> 其他 agent 只要认 SKILL.md 约定,同样装法;不当 skill 用也行,直接按下面的命令手动跑。

### 手动跑流水线

```bash
python3 doctor.py                                   # 0 体检:告诉你缺什么、怎么补
python3 seed_reverse.py 目标.mp4 --out run/shotlist.json
python3 needed_assets.py run/shotlist.json          # 按清单准备产品图 → 填 assets.json
python3 plan_segments.py run/shotlist.json assets.json --out run/segments.json   # ★人审 run/segments.md
python3 tts_segments.py run/segments.json --out-dir run/audio/seg
python3 gen_segments.py run/segments.json --clips run/clips --audio-dir run/audio/seg [--i2v-backend ark]
python3 assemble.py run/segments.json --clips run/clips --audio-dir run/audio/seg --out run/output/FULL.mp4
python3 judge.py run/output/FULL.mp4 --target 目标.mp4
python3 export_subs.py run/segments.json --shotlist run/shotlist.json --out run/output/FULL
python3 deliver.py run/segments.json --mode both --clips run/clips --audio-dir run/audio/seg \
        --shotlist run/shotlist.json --name 我的项目   # 剪映草稿箱直接出现,进去就能剪
```

## 资产与标注层(2026-08 新增)

复刻里几乎所有"看着就假"的毛病 —— 产品被编、人物切镜变脸、场景每段一个样、说话人对不上 ——
**是同一个病**:画面里出现了某个东西,而它在提示词里**没有任何图作为身份来源**,
于是模型每次自己编一个,每次编得都不一样。

所以在"反推"和"生成"之间插了一层:先问清楚这条片需要哪些身份来源,谁来准备,再开始烧钱。

### 谁来准备什么(分工是有硬理由的,不是随便分的)

| 资产 | 谁准备 | 为什么 |
|---|---|---|
| **产品** | **你** | AI 编不出你的真品;而且 h3 **画不对汉字**,带印刷文字的包装只能用真图(实测:改两轮措辞都压不住,参考图上有字它就要抄) |
| **道具** | **看情况** | 带品牌/特定外观的(你的包装盒、印字物料)→ 你准备;通用道具(毛巾/水盆/镜子)→ 不做资产,模型本来就画得对 |
| **人物** | **AI 生成,你审** | 铁律:**一律生成新身份,绝不照搬原片出镜人的肖像**——复刻别人视频时不该这么做。你只需过目角色表 |
| **场景** | **AI 生成,你审** | 场景板只定空间关系和色调,不含人物 |
| **声音** | 复用原音 | 复刻场景直接按段切原片音频 |

### 你实际要做的只有两件事

1. **按购物清单准备产品图**(`needed_assets.py` 会列出来,并标好【要你准备】)
2. **过目两张表**:角色表(`cast_plan`)和说话人表(`speaker_tag`)

其余全是机器的活。**人审只在这两个点,之后不需要你再看一眼** —— 因为剩下的是"闸"不是"审":

- **审 = 人看**:聚类是关键词匹配,可能把两个人合成一个。合错的代价是**两个不同的人共用一张脸**,
  比没有人设图更糟,机器判不了这个,只能你看。拿不准就回原片抽帧看,`目标.mp4` 就在 run 目录里。
- **闸 = 机器查**:`director.py` 12 条规则机械比对"提示词提到了 X" ⇄ "参考图里有没有 X",
  以及单段参考图有没有超上限、prompts/ 和 plan 有没有漂移。**不需要你看一眼**。

### 资产库(跨片复用)

`assets_lib/`(`DAIHUO_ASSETS_LIB` 可覆盖):

```
assets_lib/
  index.json              人物索引:name/desc/aliases/pronoun/sheet
  cast/<id>/sheet.png     3:4 人设图(上排三肖像+下排三全身,灰底影棚,赤脚)
  scene_index.json        场景索引
  scene/<key>/plate.png   场景板(不含人物)
```

同一个"大哥"出现在两条片里,第二条直接命中库存,不用重出图。
⚠**别名宁窄勿宽**:实测把"黑背心运动大哥"写进"黑短袖大哥"的别名,回原片抽帧发现是两个人
——别名过宽 = 把错误的人设图绑到别人身上,比没有人设图更糟。

### 几条实测结论(改之前先读)

- **人设图规格**:3:4 上排三肖像+下排三全身。单张正面锚图会出**严重重影**(模型把它当图层合成),
  横排六视角会把人画老画暗 —— 四版对照测出来的,别自己改规格。
- **单段参考图上限 4**(2人设+1产品+1场景板)。要少的是**同一个主体上的冗余参考**,
  不是**不同主体各自的那一张**:实测把两个角色绑到同一张合成图上,小男孩会被复制成两个。
  **"一图一人"的绑定不能省。**
- **单主播口播/vlog 不要建演职表**:多日换装会被聚成一堆假角色(发箍/手镯/戒指都不是人),
  `cast_plan` 有闸会拦住并提示。
- **h3 的 first_frame 与「音频+参考图」不能混用**(接口返回 2013),
  所以 RHTV 那套"首帧图定死构图"的强控法在带音频驱口型的口播段上走不通。

### assets.json:产品档案(换品类不改代码)

```jsonc
{"host_anchor": "assets/host.jpg",              // 主播锚定图(纯产品视频可空)
 "host_desc": "齐肩黑发,米白色针织上衣",          // ★钉进每个口播段,治跨段穿着漂移
 "product_desc": "XX鲜蒸海参,深蓝金色包装",       // 材质/颜色写死
 "products": {"hero": "...", "礼盒": "...", "内包装": "...", "单根": "..."},
 "forms": {"hero": ["精华","滴管"], "瓶身": ["玻璃瓶","泵头"]},  // ★形态别名,换品类必配
 "product_verbs": ["涂抹","上脸","拍打"],       // ★该品类操作动词,完备性关卡用
 "host_is_sheet": false,                        // 主播锚图是 3:4 人设图时置 true(**换图必须同时换措辞**)
 "exclude_forms": {"S13": ["盒装"]},             // ★逐段禁用某产品形态(治"h3 画不对包装汉字")
 "extra_constraints": {"S9": "..."}}            // 逐段追加约束(写这里,改提示词活不过下次重生成)
```

配套的两个 run 级文件(由 cast_plan / scene_plan 生成,人审后使用):

```jsonc
// cast.json —— 演职表
{"roles":[{"key":"yeshi_dage_hei","lib_id":"yeshi_dage_hei","name":"黑短袖大哥",

```

品类特定知识(形态词/动词/多音字)全走配置,默认档案偏食品/生鲜(项目出身)。

## 为什么可信

- **每个"验证过的配置"都写了为什么**(`DESIGN.md` §3):按硬切分段而非台词、真图 image2video 保质感与包装文字、thinking 关+流式快 17 倍、直连不代理……改之前先读。
- **三道判断闭环**:完备性关卡(提示词漏没漏产品动作)→ 人审闸口(烧积分前过稿)→ 评委(三看漏斗打分+真保真度对比)。
- **踩过的坑全部固化进代码**:下载截断、NAL 拼接错、口型对不上、多音字、大文件超上传上限、配音超长截尾……见 `SKILL.md` 坑索引。

## 缘起

这套东西不是先有架构再实现的,是从"为什么 agent 复刻反而不如手工"这个疑问一步步逼出来的:翻旧管线找到病根(转换丢细节,不是模型不行)→ 单案例闭环验证 → 换产品迁移验证 → 跨类目重构验证 → 把每步固化成可插拔引擎,踩一个坑修一个固化一个。它不是"一句 prompt 一键出片",而是**一个懂行的操作台 + 一本打法手册**:把手工时脑子里的高频判断显式化、可复用、可审。

## 交付两种形态(deliver.py)

- **剪映草稿(推荐)**:管线的分段结构直接透传进剪映——视频轨逐段摆(段边界即切割点)、配音轨对位、字幕轨逐句可改、原片贴字按时间点放成参考轨、空 BGM 轨等你拖音乐。素材 copy 进草稿目录自包含。实测剪映 10.7:保存草稿加密,但**读明文草稿正常**;剪映升级若失效,降级 final 模式。
- **烧字幕成品**:在中性母版 FULL.mp4 上烧字幕(+可选 `--bgm`),能直接投的及格版。FULL.mp4 永远保持无字幕无 BGM——它是评委输入和回归基准,观感加工全在下游。

## 群戏(多角色情景剧)

单主播之外,三角色办公室短剧已实战验证:逐段按出镜角色挂多张人物锚定图 + 逐角色人设声明 + **人数硬约束**(不加会幻觉多生成人物,`patch_cast.py` 已固化);产品未登场的段剥离产品图防剧透。**口型错乱治理已有完整打法**(实测错误率 28%→6%):帧级口型质检(`qc_lipsync.py`,原片帧当真值)定位脏段 → 抽卡循环(每段 1-2 抽、新旧择优)收敛随机错 → 同句两轮同错的粘性错误给时间码进剪映手修。教训:**不要**用视频模型看 AI 成片转写台词做质检——会整段幻听。复用原音时,字幕轴用分镜表镜级时间构造,精确对齐。

## 反推的可信度分工(双反推)

两个反推模型错误呈镜像:Seed 病在时序粗+贴字幻听进台词,K3 病在**实体幻觉**(把三角皂看成馒头、卸妆棉看成洗脸扑都真实发生过)。所以:时间轴/运镜细节可信 K3,**实体一律 Seed 基底+原片帧终审**,`merge_reverse.py` 出逐镜对照档案和分歧抽帧,裁决按字段不按整包。产品长相/道具/谁在场这类拍点,写提示词前必须抽帧验证——这是烧积分前最便宜的保险。

### 2026-08-19 · 资产与标注层(治切镜变脸 + 说话人错乱)

一条夜市街采片暴露出:整个 schema 只有 `host_anchor`(**单数**),多个人物**没有地方可以住**
—— 17 段里 16 段送进模型的参考图**一张人脸都没有**,却按音频驱口型提交,等于让模型对着人声凭空编人。
切镜变脸是必然,**不是模型能力问题**(同批另外三条单主播片挂图率 8~13/15,观感就正常)。

- **演职表**:人物绑成 `<Subject N>` + `Cast constraint` 钉确切人数;3:4 人设图规格由 A/B/C/C2 四版实测定
- **说话人标注**:44 个有台词的镜里 **15 个是画外旁白**,改前那 15 镜的人全在对着画外音张嘴
- **场景板**:58 镜写出 43 种场景说法(每镜描述一个略微不同的地方,本身就是漂移源)→ 收敛成 2 个场景
- **参考图限流**:单段 ≤4,优先保住【有台词的说话人】的人设图 + 1 张产品图
- **稳定性**:1027 文本审查随机拒 → 原样退避重试;上传/即梦 CLI 网络抖动重试

★三条最贵的教训(全写在 `HANDOFF.md`):
1. **1027 审查是随机的** —— 同一段文本先过后拒、原样重试又过。我按措辞猜了四轮全是追假目标,
   代价不只是钱,是**会让你误以为找到了原因**。
2. **`prompts/` 曾是死产物** —— `gen_segments` 只读 `segments.json`,全仓没有代码读 `prompts/`。
   h3_prompt 报成功、director 报全过、生成报出片,**三个环节全绿**,而用的是上一版旧提示词,
   白烧一整轮 17 段才靠肉眼看出来。现已改为默认灌回 plan + 加漂移闸。
3. **提示词自相矛盾是头号病,已第三次出现**(换装 / 包装文字 / 旁白镜说话)。
   **两句话打架时模型只会挑一句听,而且经常挑错那句 —— 不能靠加更强的约束去压,必须把打架的那句删掉。**


按时间倒序。每条只写"这一版解决了什么问题",细节见对应 commit 与 `SKILL.md` 坑索引。

### 2026-08-10 · 渠道价 ≠ 模型价(推翻前一版的成本结论)

- **前一版(08-09)基于 RunningHub 报价得出的"h3 比即梦贵"是错的。** H3 的真实价格是 **¥0.09~0.11/秒**(MiniMax 官方规范 + 秘塔转售),比即梦 VIP 便宜 7 倍;RunningHub 的 ¥0.48/秒里差的全是渠道加价。新增 `mmh3_gen.py`(base_url 可换渠道,不把自己焊死在一家),**RunningHub 退役**。
  → **接任何新后端先问:这是渠道价还是模型价?有没有更靠近源头的通道?**
- **生图改走即梦 `text2image --model_version 5.0 --resolution_type 2k`,实测 0 积分**(订阅权益"图片5.0Lite 2K限时免费"),1440×2560 比原先 ¥0.1/张的方案又免费又高一档。铁律不变:**带品牌文字的产品图一律不生成,只用真图**。
- **按腿路由落地**:`plan_segments --by-leg` 同段必须同腿并打 `leg` 标记(package_text→h3 / hero_real→即梦 / 其余→h3),内置**临界点合并**(拆细与最短时长对冲,mmh3 碎段短于 0.6 秒自动并回);`gen_segments --auto-leg` 按段派发,h3 段并发、即梦段串行。实测同一条片 ¥14.07→¥12.09 且每段同腿。
- **四方对照实证**:同锚图同音频同内容下,**即梦 2.0 是唯一锚得住产品三维形体的**(h3 两个独立渠道都画错,且错法不同 → 系统性失败,抽卡救不回来);而 **h3 的平面印刷图案锚定零错**(logo/毛笔字/三列小字)。分工由此确定,不是"谁更强"而是"各强在哪"。
- **即梦非VIP慢速档判死**:一枪 5 秒的任务排队 **15 小时 40 分钟**仍在 Queueing 且占死并发槽。省 43% 换"不知何时出片",默认改回 `seedance2.0_vip`。另发现 **VIP 与非VIP 各有一个独立并发槽**。

### 2026-08-09 · 第四条生成腿 + 成本三层治理(★成本结论已被 08-10 推翻,见上)
- **新增 `rh_gen.py`(RunningHub 海螺 h3)**:即梦之外**唯一能音频驱动口型**的口播后端,`--mm-backend rh` 切换。实测 30.5s 带货片 10 段一次过审、零重试。
- **并发**:`gen_segments --concurrency N`。RH 实测 3 段同时提交真并行(完成间隔 17-23 秒);**即梦 CLI 通道账号级限流=1**,多提必 `ret=1310`,换 `--session` 无效——已在代码里区分,只对验证过的后端开并发。
- **成本要算三层,不能只看单价**(即梦季卡口径 ¥0.053/积分):
  | 通道 | ¥/秒 | 并发 | 时延 |
  |---|---|---|---|
  | 即梦 `seedance2.0` 非VIP慢速 | 0.424 | 1 | 60分钟+ |
  | RH 海螺 h3 768P | 0.48 | ≥3 真并行 | ~3分钟 |
  | 即梦 `seedance2.0_vip` | 0.742 | 1 | 几分钟 |
  | RH 海螺 h3 2K | 0.77 | ≥3 | ~3分钟 |
  | 即梦 `seedance2.5` | 1.378 | 1 | ~2分钟 |
  第二层是**后端最短生成时长的浪费**:h3 最短 5 秒,快切片每段真实跨度才 1~3 秒 → 曾有 39% 的钱花在被裁掉的画面上。新增 `plan_segments --min-dur/--hard-max-cuts` 填满模式,降到 28%。第三层是重抽率。
- **装配/交付修正**:`assemble --trim-to-plan`(各后端产物都比规划跨度长,不裁则段尾空窗+全片撑长)、`--master-audio`(A 模式整条原音直铺)、`--size`(2K 素材别被压回 720p);`deliver` 同步这两个开关,否则视频轨与字幕轨对不上。
- **路由修复**:`seg_role` 的"有台词即口播"兜底改为只对旧 shotlist 开放——画外音/吃播段被误判进口播会拿产品镜去对口型,钩子直接丢。
- **新规律**:生图模型会改字、视频模型的参考图是锚定不改字(同一纸盒双向实证);状态参考图会连带迁移它的背景与光照;`judge` 压缩小版上传后会看漏,差距清单必须逐条核实再采信。
