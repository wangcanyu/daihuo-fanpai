# 位置权重 A/B 实验方案(09-05，待即梦积分充足时跑)

## 背景

上游 seedance-2.0 v6.7 的 `prompt_architecture_stress.py` 用 102 条提示词 × 3 种写法
机械打分，实证"开头子句权重最贵"(Director Formula 臂 3.92 过线，其余两臂不过)。
而我们的即梦中文提示词是**绑定句占开头**("@图片1是带货主播本人…每一个镜头都保持
与@图片1完全一致"),动作在中间 —— 和上游"主体+动作必须占开头"的教义相反。

谁对？不知道，我们从没测过位置效应。本实验把这个问题从信仰变成证据。

## 假设与判据

- H0(现状):绑定句前置不影响动作保真与锚定 → 维持现状
- H1:动作前置提升动作保真(代价可能是身份锚定变弱) → 考虑调整模板

判据(逐段双盲抽帧):
- 动作保真:反推 action 里的关键动作在成片里出现了几个(完备性关卡口径)
- 身份锚定:成片人脸 vs 锚图的相似度(人眼/qc_lipsync 帧对照)

## 实验设计

同一内容、同一锚图、同一音频,只变提示词语序:

- A 臂(现行):绑定句开头 → 场景 → 动作 → 台词 → 约束尾
- B 臂(上游教义):主体+动作开头 → 场景 → 绑定句 → 台词 → 约束尾

用一条真实短段(4~6s 口播段,如烧烤料 S2)两臂各抽 2 次(防批次方差,
"坏帧先重摇"铁律),共 4 枪。即梦 VIP 14 积分/秒 → 约 6s×14×4 ≈ 336 积分。
**积分不足时不跑**(2026-09-04 时余 70)。

## 执行(积分充足后)

```bash
# 1. 从任一 run 的 segments.json 取一段 mm 口播段,拷贝两份 prompt
# 2. B 臂手工把动作描述挪到段首、绑定句挪到动作之后(其余一字不动)
# 3. 两臂各跑 2 次:
python3 gen_segments.py <seg_armA>.json --clips clips/armA --audio-dir run/audio/seg --only S2
python3 gen_segments.py <seg_armB>.json --clips clips/armB --audio-dir run/audio/seg --only S2
# 4. 抽帧对照:每臂首尾各 2 帧,先判动作保真再判身份锚定
```
