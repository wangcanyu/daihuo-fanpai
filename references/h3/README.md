## 硬规(都是拿钱试出来的)

1. **审查只审 prompt 文本,不审图片和音频。** 台词原文、价格词("大几十")、"内脏"这类词写进 prompt 会被
   "内容安全审查未通过"拒掉(不计费但白等一轮)。
   → **口播段的台词一律不进 prompt**,口型靠 `audioUrls` 自带就够;产品描述先做敏感词消毒。
   ⚠ 这条和即梦的 TNS 正相反(即梦审的是人脸/图片),**两边的消毒策略不能互相套用**。
2. **产物比请求时长多约 0.5s 尾帧** → 装配必须 `assemble.py --trim-to-plan`,否则段尾"音已停画还在演"。
3. **结果 URL 只活 24 小时**,拿到即落盘;`rh_gen.wait_download` 已内置。超时不代表失败,
   taskId 存在 `clips/<seg>.meta.json`,`python3 rh_gen.py --fetch <taskId> --out x.mp4` 补抓,不重复扣费。
4. **口型证据的边界**:实证测的是"产物音轨 vs 输入 wav 的 0.5s 窗 RMS 包络相关 0.976"——这只证明
   **原音被 1:1 复用且零偏移**,口型对不对是肉眼判的。**换新片首用时先跑 `qc_lipsync.py` 帧级验收再批量。**
5. **段内多镜身份保持弱于即梦**:参阿婆 S1 第三镜主播护目镜漂成细框眼镜、领夹麦消失。
   长段(>8s 且段内有硬切)优先拆段,或仍走即梦。
6. seedream4.5 文生图 **总像素必须 ≥3,686,400**,9:16 用 1440×2560(¥0.2/张)。
   用途:A 模式想换掉原片主播长相时,生一张新主播锚图(比抽原片帧更干净,也避开肖像问题)。
7. 参考视频(`submit_r2v`)**必须先 `ffmpeg -an` 剥音轨**,带配乐会触发版权闸整单拒(和小云雀同款坑)。

## 提示词写法(Ref2VA 六段式)

MiniMax 官方规范全文在同目录 `SKILL.md` / `base-en.txt` / `ref-en.txt`。要点:

- 全参考模式(多图+音频)用六段,顺序不能乱:
  `subject_definitions` → `summary` → `retention_analysis` → `detailed_description`
  → `overall_soundscape` → `non_diegetic_music`
- 正文写英文;台词/歌词/画面上要出现的文字保留原语言——但按上面硬规 1,**带货口播段的台词干脆不写**。
- 段内硬切用 `[Shot N] At MM:SS.mmm` 调度。实测听话:撕袋→蘸水→举参三镜的顺序、4.3s/6.1s 两个切点都踩准了。
- `plan_segments.py` 出的是即梦风格的中文提示词。走 rh 的口播段建议按六段式重写一版
  (参阿婆工程是逐段手写 `H3_PROMPTS` 的),i2v 段直接用原提示词即可。

## 成本估算(08-09 实测口径)

| 分辨率 | ¥/秒 | 说明 |
|---|---|---|
| 768P | **¥0.48** | 比即梦 VIP 便宜,但比即梦非VIP慢速档(¥0.424)贵 |
| 2K | **¥0.77** | **比即梦 VIP(¥0.742)还贵**,只在确实要 2K 时用 |

提交时 `rh_gen` 会按分辨率打印单段预估。**算总价时别忘了 h3 的 5 秒下限**:
快切片每段真实跨度才 1~3 秒时,一样按 5 秒收费——08-09 李时珍片 10 段 × 5 秒 = 50 秒的账
对着 30.5 秒的成片,39% 的钱花在被裁掉的画面上。**开填满模式**(`plan_segments --min-dur 5
--hard-max-cuts 4`)能把浪费压到 28%。

**开跑前把总价算给用户看,拿到明确同意再提交。**

RH 是**渠道价不是模型价**(回执字段 `thirdPartyConsumeMoney` = 转手第三方 API)。
自部署/云端部署 h3,720p 可望压到 ¥0.1/秒量级——上规模后值得折腾,当前不折腾。
